ステップ１：【BindingResult の宣言位置】に関する問題

問１. 以下のコードの説明として誤っているものを選べ。

---Java---
@Controller
public class ItemController {

    // パターンA
    @PostMapping("/item/register")
    public String registerA(@Validated ItemForm form,
                            Model model,
                            BindingResult result) {
        if (result.hasErrors()) {
            return "item/form";
        }
        return "redirect:/item/list";
    }

    // パターンB
    @PostMapping("/item/update")
    public String registerB(@Validated ItemForm form,
                            BindingResult result,
                            Model model) {
        if (result.hasErrors()) {
            return "item/form";
        }
        return "redirect:/item/list";
    }
}
----------

1. パターンBは正しい定義であり、BindingResult は @Validated を付与した引数の直後に宣言している。
2. パターンAは誤りであり、BindingResult は @Validated を付与したフォームクラスの引数の直後に置かなければならない。
3. パターンAでは BindingResult が Model の後に宣言されているため、バリデーション結果が正しく取得できない。
4. @Validated と BindingResult はどの順番で宣言しても動作は同じであるため、パターンAとパターンBは等価である。

正解：4番

ステップ２：【@Valid と @Validated の違い】に関する問題

問２. @Valid と @Validated の違いに関する説明として正しいものを選べ。

1. @Validated はグループバリデーションをサポートしており、@Valid は標準のBean Validationアノテーションである。
2. @Valid は Spring Framework 独自のアノテーションであり、@Validated は標準のBean Validationに含まれる。
3. @Valid と @Validated はまったく同じ機能であり、どちらを使っても動作に違いはない。
4. @Validated はフォームクラスにのみ付与可能であり、メソッドの引数には使用できない。

正解：1番

ステップ３：【th:object と th:field の組み合わせ】に関する問題

問３. 以下のコードの説明として正しいものを選べ。

---Thymeleaf---
<form th:action="@{/user/register}" th:object="${userForm}" method="post">
  <input type="text" th:field="*{userName}">
  <span th:errors="*{userName}">エラー</span>
  <button type="submit">登録</button>
</form>
----------

1. th:object="${userForm}" でフォームオブジェクトを指定し、th:field="*{userName}" で対象フィールドを選択変数式で参照している。
2. th:object="${userForm}" は不要であり、th:field="${userForm.userName}" のように直接変数式で指定すべきである。
3. th:field="*{userName}" は th:object の指定に関係なく、常にモデル全体からフィールドを探す。
4. th:errors="*{userName}" はエラーメッセージをコントローラに送り返すための属性である。

正解：1番

ステップ４：【findById の戻り値型（Optional）と get() の扱い】に関する問題

問４. 以下のコードの説明として誤っているものを選べ。

---Java---
@Service
public class ProductService {

    @Autowired
    private ProductRepository productRepository;

    public Product getById(Integer id) {
        Optional<Product> result = productRepository.findById(id);
        return result.get();
    }
}
----------

1. findById() の戻り値型は Optional<Product> であり、レコードが存在しない場合は空の Optional が返される。
2. result.get() はレコードが存在する場合に Product を取り出せるが、レコードが存在しない場合は例外が発生する可能性がある。
3. レコードが存在しない場合に安全に処理するには、result.isPresent() で確認するか、result.orElse() を使うべきである。
4. findById() の戻り値型は Product 型であり、レコードが存在しない場合は null が返される。

正解：4番

ステップ５：【save() の新規登録・更新の自動切り替え】に関する問題

問５. 以下の2つのコードに関する説明として正しいものを選べ。

---Java（新規登録）---
Product product = new Product();
product.setProductName("りんご");
product.setPrice(150);
// idはセットしない
productRepository.save(product);
----------

---Java（更新）---
Optional<Product> opt = productRepository.findById(5);
Product product = opt.get();
product.setPrice(200);
productRepository.save(product);
----------

1. save() はエンティティに主キー（id）が設定されていない場合は新規登録（INSERT）、設定されている場合は更新（UPDATE）を自動的に判定する。
2. save() は常にINSERTを実行する。更新にはupdate()メソッドを別途使用する必要がある。
3. save() はエンティティのフィールド数に応じてINSERTかUPDATEかを自動判定する。
4. 更新処理では、save() の前に delete() を呼び出して既存レコードを削除する必要がある。

正解：1番

ステップ６：【@NamedQuery と @Query の定義場所の違い】に関する問題

問６. @NamedQuery と @Query の定義場所に関する説明として正しいものを選べ。

---Java（パターンA：@NamedQuery）---
@Entity
@NamedQuery(
    name = "Product.findByCategory",
    query = "SELECT p FROM Product p WHERE p.category = :category"
)
public class Product {
    // フィールド省略
}
----------

---Java（パターンB：@Query）---
public interface ProductRepository extends JpaRepository<Product, Integer> {

    @Query("SELECT p FROM Product p WHERE p.category = :category")
    List<Product> findByCategory(@Param("category") String category);
}
----------

1. @NamedQuery はエンティティクラスに定義し、@Query はリポジトリインターフェースのメソッドに定義する。
2. @NamedQuery はリポジトリインターフェースに定義し、@Query はエンティティクラスに定義する。
3. @NamedQuery と @Query はどちらもリポジトリインターフェースにのみ定義できる。
4. @NamedQuery と @Query はどちらもエンティティクラスにのみ定義できる。

正解：1番

ステップ７：【HttpFilter の doFilter と chain.doFilter の役割】に関する問題

問７. 以下のコードの説明として正しいものを選べ。

---Java---
@Component
public class LoggingFilter extends HttpFilter {

    @Override
    protected void doFilter(HttpServletRequest request,
                            HttpServletResponse response,
                            FilterChain chain)
            throws IOException, ServletException {

        System.out.println("リクエスト前の処理");
        chain.doFilter(request, response);
        System.out.println("レスポンス後の処理");
    }
}
----------

1. chain.doFilter(request, response) を呼び出すことで、次のフィルターまたはサーブレットへ処理を引き渡す。
2. chain.doFilter(request, response) を省略しても、後続の処理（コントローラへのルーティング）は自動的に実行される。
3. @Component を付与しなくても、HttpFilter を継承したクラスは自動的にフィルターとして機能する。
4. doFilter メソッドは HttpFilter を継承したクラスでオーバーライドできない。

正解：1番

ステップ８：【FilterRegistrationBean による実行順序制御】に関する問題

問８. 以下のコードの説明として正しいものを選べ。

---Java---
@Configuration
public class FilterConfig {

    @Bean
    public FilterRegistrationBean<LoggingFilter> loggingFilter() {
        FilterRegistrationBean<LoggingFilter> bean = new FilterRegistrationBean<>();
        bean.setFilter(new LoggingFilter());
        bean.setOrder(1);
        return bean;
    }

    @Bean
    public FilterRegistrationBean<AuthFilter> authFilter() {
        FilterRegistrationBean<AuthFilter> bean = new FilterRegistrationBean<>();
        bean.setFilter(new AuthFilter());
        bean.setOrder(2);
        return bean;
    }
}
----------

1. setOrder の値が小さいほど先に実行されるため、LoggingFilter が AuthFilter より先に実行される。
2. setOrder の値が大きいほど先に実行されるため、AuthFilter が LoggingFilter より先に実行される。
3. setOrder を指定しない場合、フィルターは定義した順番に関係なくランダムに実行される。
4. FilterRegistrationBean を使わない場合、複数フィルターの実行順序を制御する方法は存在しない。

正解：1番

ステップ９：【@ManyToOne + @JoinColumn の複合的な読み取り】に関する問題

問９. 以下のコードの説明として誤っているものを選べ。
ただし、DBには「orders」テーブルと「customers」テーブルが存在し、orders テーブルには「customer_id」列（外部キー）があるとする。

---Java---
@Entity
@Table(name = "orders")
public class Order {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Integer id;

    @ManyToOne
    @JoinColumn(name = "customer_id")
    private Customer customer;

    private Integer amount;

    // getter/setter 省略
}
----------

---Java---
@Entity
@Table(name = "customers")
public class Customer {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Integer id;

    private String customerName;

    // getter/setter 省略
}
----------

1. Order エンティティの customer フィールドに Customer エンティティのオブジェクトをセットすることで、外部キー（customer_id）が自動的にDBに保存される。
2. @JoinColumn(name = "customer_id") は、orders テーブルの「customer_id」列が外部キー列であることを示す。
3. @ManyToOne により「1人の顧客が複数の注文を持てる」関係が表現されている。
4. Order エンティティを save() する際、@JoinColumn を記述しているため Customer も同時に自動で新規登録される。

正解：4番

ステップ１０：【result.hasErrors() による分岐とリダイレクトの組み合わせ】に関する問題

問１０. 以下のコードの説明として正しいものを選べ。

---Java---
@PostMapping("/member/register")
public String register(@Validated MemberForm form,
                       BindingResult result,
                       Model model) {
    if (result.hasErrors()) {
        return "member/form";
    }
    memberService.save(form);
    return "redirect:/member/complete";
}
----------

1. バリデーションエラーがある場合は "member/form" ビューに（フォワードで）遷移し、エラーがない場合はリダイレクトで「/member/complete」に遷移する。
2. バリデーションエラーがある場合もリダイレクトで "member/form" に遷移するため、ブラウザのURLが変わる。
3. result.hasErrors() が true の場合、memberService.save(form) も実行されてからビューに遷移する。
4. "redirect:/member/complete" はビュー名として解釈されるため、「redirect」という名前のフォルダ内の complete.html を探す。

正解：1番

ステップ１１：【th:switch / th:case による多分岐】に関する問題

問１１. 以下のコードの説明として正しいものを選べ。
ただし、コントローラから "status" という名前で「2」が渡されているとする。

---Thymeleaf---
<div th:switch="${status}">
  <p th:case="1">受付中</p>
  <p th:case="2">処理中</p>
  <p th:case="3">完了</p>
  <p th:case="*">不明</p>
</div>
----------

1. status が「2」であるため、「処理中」のみが表示される。
2. status が「2」であるため、「受付中」「処理中」「完了」がすべて表示される。
3. th:case="*" はすべての値に一致するため、常に「不明」が表示される。
4. th:switch は文字列型の値にのみ対応しており、数値型は使用できない。

正解：1番

ステップ１２：【th:fragment / th:replace によるレイアウト機能】に関する問題

問１２. 以下のコードの説明として正しいものを選べ。

---Thymeleaf（共通ヘッダー fragments/header.html）---
<!DOCTYPE html>
<html xmlns:th="http://www.thymeleaf.org">
<body>
  <header th:fragment="siteHeader">
    <h1>共通ヘッダー</h1>
    <nav>ナビゲーション</nav>
  </header>
</body>
</html>
----------

---Thymeleaf（個別画面 top.html）---
<!DOCTYPE html>
<html xmlns:th="http://www.thymeleaf.org">
<body>
  <div th:replace="~{fragments/header :: siteHeader}"></div>
  <main>
    <p>メインコンテンツ</p>
  </main>
</body>
</html>
----------

1. th:replace="~{fragments/header :: siteHeader}" により、fragments/header.html の th:fragment="siteHeader" で定義されたブロックが div タグごと置き換えて埋め込まれる。
2. th:replace は div タグの内側にのみ挿入し、div タグ自体は残る。
3. th:fragment はコントローラクラスに付与するアノテーションであり、HTMLファイルには記述できない。
4. th:replace を使用するには、レイアウト用の外部ライブラリ（Thymeleaf Layout Dialect）が必須である。

正解：1番
