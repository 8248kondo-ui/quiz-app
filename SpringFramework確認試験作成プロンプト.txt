================================================================
Spring Framework 確認試験 例題作成用プロンプト
================================================================

あなたはSpring Framework（Java）プログラミングの研修講師です。
以下の箇条書きで示したトピックに基づき、確認試験形式の例題を作成してください。

================================================================
【基本作成ルール】
================================================================
1. 各トピックにつき、四択の選択問題を1問作成すること
2. 問題文は「〜として正しいものを選べ」または「〜として誤っているものを選べ」の形式とすること
3. 選択肢は1〜4の番号で示し、正解は1つだけとすること
4. 各問題の末尾に「正解：〇番」と正解番号を明示すること
5. 問題はトピックごとにグループ分けし、見出しをつけること
   （例：「コントローラ」「バリデーション」「Thymeleaf」など）
6. 出力は日本語で行うこと

================================================================
【コードを含む問題の作成ルール】★重要★
================================================================
■ Spring Framework では「コードの読み取り問題」を積極的に出題すること

1. コード問題の出題パターン（以下のいずれかを使うこと）

   パターンA：コードを見て「何をしているか」を答える問題
   例：「以下のコードの説明として正しいものを選べ」

   パターンB：コードを見て「正しい／誤っているものを選べ」
   例：「以下のコードに関する説明として誤っているものを選べ」

   パターンC：アノテーション・属性・記述の「穴埋め」問題
   例：「以下のコードの（　）に入る記述として正しいものを選べ」

   パターンD：コードの実行結果・画面遷移先を問う問題
   例：「以下のコントローラが実行された後、遷移する先のビュー名として正しいものを選べ」

2. コードはかならずコードブロック（---Java--- 形式）で囲んで表示すること
3. 複数言語（Java + HTML）を組み合わせた問題では言語名を分けて記載すること
   例：---Java--- と ---Thymeleaf--- を別ブロックで表示
4. 変数・フィールドに事前に値が入っている前提の場合は問題文に明示すること
   例：「ただし、フォームクラス SampleForm の name フィールドには "田中" が格納されているとする。」
5. 問題文の基本形：「以下のコードの説明として正しいものを選べ。」

================================================================
【選択肢・ひっかけの設計ルール】★重要★
================================================================
■ NG：以下は絶対にしないこと
- 「SQL文法」「正規化」「インデックス設計」「シーケンス」などのDB設計用語を
  SpringのコアトピックのひっかけとしてSpring問題に混入させないこと
- Spring固有の概念（DIコンテナ、アノテーション、スコープ等）と
  無関係な技術用語（サーブレット直書き・struts等）をひっかけに使わないこと

■ OK：同一トピック・同一概念内でのひっかけを使うこと
- アノテーションの混同（例：@GetMapping と @PostMapping、@Controller と @RestController）
- スコープの混同（例：リクエストスコープ ↔ セッションスコープ）
- フォワードとリダイレクトの混同（URLが変わるかどうか、通信回数など）
- 引数・戻り値の役割の混同（例：Modelへの追加とセッション保存を混同させる）
- Thymeleaf属性の混同（th:text / th:value / th:errors / th:object など）
- Bean Validationアノテーションの混同（@NotNull / @NotBlank / @NotEmpty の違い）
- BindingResultの位置（「引数の直後に置く必要がある」という仕様の誤解を突く）
- メッセージ式の混同（#{...} / ${...} / @{...} / *{...} の使い分け）
- findById の戻り値型の混同（Optional型 ↔ エンティティ直接 ↔ null）

================================================================
【Spring固有のひっかけパターン一覧】
================================================================
- 【アノテーション】@Controller vs @Service vs @Repository の役割の取り違え
- 【アノテーション】@RequestMapping(method=GET) vs @GetMapping / @PostMapping の違い
- 【アノテーション】@Autowired の付与対象（フィールド/コンストラクタ/セッター）
- 【遷移】return "redirect:/xxx" の "redirect:" プレフィックスの有無
- 【遷移】フォワードはURLが変わらない、リダイレクトはURLが変わる
- 【Model】addAttribute の方向（コントローラ→ビュー 方向のみ）
- 【スコープ】session.getAttribute / model.addAttribute の混同
- 【Thymeleaf】th:object と th:field の組み合わせの正しさ
- 【Thymeleaf】th:each でのコレクション反復の変数宣言の書き方
- 【バリデーション】@Valid vs @Validated の違い
- 【バリデーション】BindingResult を引数の直後に置く必要がある
- 【JPA】findAll() の戻り値は List 型
- 【JPA】findById() の戻り値は Optional 型
- 【JPA】save() の新規/更新の自動切り替え（IDの有無で決まる）
- 【フィルタ】HttpFilter の doFilter のオーバーライドと chain.doFilter の呼び出し

================================================================
【難易度の設計ルール】
================================================================
- 基礎レベル：アノテーションの名前・役割、スコープの種類と寿命、画面遷移の仕組み
- 中級レベル：コードを読んで処理・遷移先を答える、アノテーション属性の正誤判断
- 応用レベル：複数アノテーションの組み合わせ、BindingResult の位置、
             @JoinColumn + @ManyToOne の関係、フィルタの実行順序制御

================================================================
【選択肢の表現ルール】
================================================================
1. 正解の選択肢は簡潔・具体的に書くこと
   OK例：「コントローラからビューへデータを渡すためのメソッドである。」
   NG例：「モデルにデータ（items変数）を入れてビューに渡すメソッドである（リクエストスコープに格納）」

2. 誤答の選択肢は以下のパターンを使い分けること
   パターンA：対象を1つずらす（例：「ビューから受け取る」→「コントローラから渡す」の逆）
   パターンB：スコープの方向・種類を入れ替える（リクエスト ↔ セッション ↔ アプリケーション）
   パターンC：似たアノテーションと入れ替える（@Controller ↔ @Service ↔ @Repository）
   パターンD：部分的に正しいが細部が誤り（例：「Optional型ではなくエンティティ型で返される」）

3. 選択肢の長さをなるべく揃えること（1つだけ極端に長い・短いものを避ける）

================================================================
【出力フォーマット】
================================================================

---
ステップ〇：【トピック名】に関する問題

問〇. 〇〇として正しいものを選べ。
ただし、〇〇には〇〇が代入されているとする。（コードがある場合のみ記載）

---Java---（複数行コードがある場合のみ）
（コード）
----------

1. 〇〇
2. 〇〇
3. 〇〇
4. 〇〇

正解：〇番
---

【トピックリスト（テンプレート）】
================================================================
以下の箇条書きを、出題したいトピックに書き換えて使用してください。

■ Webの基礎
- 静的ページと動的ページの違い
- HTTPリクエストとレスポンスの仕組み
- コンテキストパスの定義

■ Springの基礎・MVC構造
- @Controller アノテーションの役割
- @RequestMapping / @GetMapping / @PostMapping の使い分け
- メソッドの戻り値（ビュー名の指定）
- フォワードとリダイレクトの違い（return "redirect:/xxx"）

■ データの受け取り（フォームクラス）
- フォームクラスの役割
- name属性と引数名の一致ルール
- GETリクエストとPOSTリクエストの使い分け

■ スコープとデータ受け渡し
- リクエスト・セッション・アプリケーションスコープの寿命の違い
- model.addAttribute の役割と方向
- セッションスコープの値をThymeleafで表示する方法（session.xxx）
- セッションタイムアウトの目的

■ JPA・エンティティ・リポジトリ
- JPA（Java Persistence API）の概要
- @Entity / @Id アノテーションの役割
- JpaRepository の主要メソッド（findAll / findById / save / delete）
- findById の戻り値型（Optional）
- save メソッドの新規登録・更新の自動切り替え

■ 外部参照（関連エンティティ）
- @ManyToOne アノテーションの意味（多対1）
- @JoinColumn の役割（外部キー列の指定）

■ JPQL
- JPQL の特徴（テーブル名でなくエンティティ名を使う）
- @NamedQuery と @Query の定義場所の違い
- JPQL の FROM 句に指定するもの

■ 入力チェック（Bean Validation）
- フォームクラスへのバリデーションアノテーション付与
- @Validated / @Valid の役割
- BindingResult の宣言位置（引数の直後）
- result.hasErrors() による分岐
- th:errors によるエラーメッセージ表示

■ メッセージ出力
- ValidationMessages.properties の用途
- messages.properties の用途と記述形式（key=value）
- Thymeleaf でのメッセージ式（#{キー名}）

■ フィルタ
- HttpFilter（doFilter メソッド）の役割
- @Component による DIコンテナへの登録
- FilterRegistrationBean と setOrder による実行順序制御

■ Thymeleaf（テンプレートエンジン）
- th:text / th:value / th:object / th:field の役割
- th:each によるリスト表示
- th:if / th:unless による条件分岐
- th:switch / th:case による多分岐
- th:errors によるエラーメッセージ表示
- #{} / ${} / @{} / *{} の使い分け（メッセージ式・変数式・URL式・選択変数式）
- th:fragment / th:replace によるレイアウト機能

================================================================
【使い方】
================================================================
1. 上記「トピックリスト（テンプレート）」から出題したい項目を選択し、
   このプロンプトの末尾に箇条書きで貼り付けてください。
2. AIに送信すると、各トピックにつき1問ずつ、四択問題が生成されます。
3. 「コードを含む問題を重点的に出題してほしい」など追記することも可能です。
