問題1　拡張for文（for-each）
-------------------------------------------------------------------
以下のコードの実行結果として正しいものを選べ。

---Java---
int[] nums = {10, 20, 30};
for (int n : nums) {
    System.out.print(n + " ");
}
----------

1. 10
2. 10 20 30
3. 0 1 2
4. コンパイルエラー

正答: 2

解説:
拡張for文（for-each文）は配列やコレクションの各要素を
先頭から順番に取り出してループします。

  for (要素の型 変数名 : 配列名) { ... }

・nums には {10, 20, 30} が入っているため、n に 10, 20, 30 の順で
  値が入り、それぞれ print で出力されます。
・System.out.print は改行しないため「10 20 30 」と1行で表示されます。

・選択肢1: 10のみでは不十分。3要素すべて処理されます。
・選択肢2: 正解。
・選択肢3: nums[0]～nums[2] ではなく、値そのものが出力されます。
・選択肢4: 正しい構文のためコンパイルエラーはありません。


問題2　拡張for文（要素の変更）
-------------------------------------------------------------------
以下のコードの実行結果として正しいものを選べ。

---Java---
int[] nums = {1, 2, 3};
for (int n : nums) {
    n = n * 10;
}
System.out.println(nums[0]);
----------

1. 10
2. 1
3. 0
4. コンパイルエラー

正答: 2

解説:
拡張for文の変数 n は、配列の要素のコピーを受け取ります。
n に代入しても配列 nums の中身は変わりません。

---Java---
for (int n : nums) {
    n = n * 10;   // nums[0] 自体は変わらない！
}
----------

そのため、nums[0] の値は最初に代入された 1 のままです。

【ポイント】
  配列の要素を変更したい場合は通常のfor文を使う。
  for (int i = 0; i < nums.length; i++) { nums[i] = nums[i] * 10; }


問題3　多次元配列（宣言と初期化）
-------------------------------------------------------------------
2行3列の二次元配列を宣言・初期化する記述として正しいものを選べ。

1. int[] matrix = new int[2][3];
2. int[][] matrix = new int[2][3];
3. int matrix[2][3] = new int[][];
4. int[2][3] matrix = new int[][];

正答: 2

解説:
二次元配列の宣言は型の後に [][] を付けます。

  int[][] 変数名 = new int[行数][列数];

・選択肢1: int[] は一次元配列の宣言であり、new int[2][3] との型が一致しません（コンパイルエラー）。
・選択肢2: 正解。int[][] matrix = new int[2][3]; が正しい。
・選択肢3・4: 型と変数名の記述順序や括弧の使い方が誤りです。

【ポイント】
  int[][] array = new int[行][列];
  要素数: 行数 × 列数


問題4　多次元配列（要素へのアクセス）
-------------------------------------------------------------------
以下のコードの実行結果として正しいものを選べ。

---Java---
int[][] grid = {{1, 2, 3}, {4, 5, 6}};
System.out.println(grid[1][2]);
----------

1. 3
2. 5
3. 6
4. コンパイルエラー

正答: 3

解説:
grid[1][2] は「1行目（0始まり）の2列目（0始まり）」の値を指します。

  {{1, 2, 3},   ← grid[0][0]=1, grid[0][1]=2, grid[0][2]=3
   {4, 5, 6}}   ← grid[1][0]=4, grid[1][1]=5, grid[1][2]=6

grid[1][2] = 6

・選択肢1: grid[0][2] の値（3）です。
・選択肢2: grid[1][1] の値（5）です。
・選択肢3: 正解。grid[1][2] = 6。
・選択肢4: 正しいアクセスのためコンパイルエラーはありません。


問題5　do-while文
-------------------------------------------------------------------
以下のコードの実行結果として正しいものを選べ。

---Java---
int i = 5;
do {
    System.out.println(i);
    i++;
} while (i < 5);
----------

1. 何も表示されない
2. 5
3. 5 6
4. 無限ループになる

正答: 2

解説:
do-while 文は「先に処理を実行してから条件を評価」します。

  int i = 5;
  do {
      System.out.println(i);  // ← 先に実行（i=5 を表示）
      i++;                     // i が 6 になる
  } while (i < 5);             // 6 < 5 は false → ループ終了

条件が最初から false でも1回は実行されるため、「5」が1回表示されます。

・選択肢1: do-while は1回必ず実行されるため誤りです。
・選択肢2: 正解。「5」が1回表示される。
・選択肢3: ループは1回で終了するため、6は表示されません。
・選択肢4: 6 < 5 は false なので無限ループになりません。


問題6　do-while文 と while文の違い
-------------------------------------------------------------------
do-while文の特徴として正しいものを選べ。

1. 条件がfalseでも必ず1回はループ内の処理が実行される。
2. 条件がfalseの場合、ループ内の処理は1度も実行されない。
3. do-while文はwhileキーワードを使用しない。
4. do-while文ではbreak文が使用できない。

正答: 1

解説:
while文とdo-while文の違い:

  while文:     条件を評価 → 真なら実行（最初から偽なら0回）
  do-while文:  実行 → 条件を評価（必ず最低1回実行される）

・選択肢1: 正解。条件が最初からfalseでも必ず1回ループ内処理が実行されます。
・選択肢2: while文の特徴であり、do-while の特徴ではありません。
・選択肢3: do-while文も while キーワードを末尾で使用します。
・選択肢4: do-while文でも break 文は使用可能です。


問題7　三項演算子
-------------------------------------------------------------------
以下のコードの実行結果として正しいものを選べ。

---Java---
int score = 75;
String result = (score >= 60) ? "合格" : "不合格";
System.out.println(result);
----------

1. 合格
2. 不合格
3. true
4. コンパイルエラー

正答: 1

解説:
三項演算子の構文:

  条件式 ? 真のときの値 : 偽のときの値

  score = 75 → 75 >= 60 は true → "合格" が代入される

・選択肢1: 正解。score(75) >= 60 は true なので「合格」が表示される。
・選択肢2: 条件が false のときの値。score >= 60 は true なので誤り。
・選択肢3: true/false はboolean値であり、三項演算子の結果は文字列です。
・選択肢4: 正しい構文のためコンパイルエラーはありません。

【ポイント】
  三項演算子は if-else 文の短縮形として使える。
  String result = score >= 60 ? "合格" : "不合格";
  ↓ 同義
  if (score >= 60) { result = "合格"; } else { result = "不合格"; }


問題8　三項演算子（ネスト）
-------------------------------------------------------------------
以下のコードの実行結果として正しいものを選べ。

---Java---
int x = 10;
String msg = (x > 0) ? "正" : (x < 0) ? "負" : "ゼロ";
System.out.println(msg);
----------

1. 負
2. ゼロ
3. 正
4. コンパイルエラー

正答: 3

解説:
三項演算子はネスト（入れ子）にできます。

  x = 10
  (x > 0) → true → "正" が返る

  (x > 0) ? "正" : (x < 0) ? "負" : "ゼロ"
  → 最初の条件 (10 > 0) が true なので "正" が確定。

・選択肢1: x < 0 のときに返る値です。
・選択肢2: x == 0 のときに返る値です。
・選択肢3: 正解。x > 0 なので "正"。
・選択肢4: 正しい構文のためコンパイルエラーはありません。

問題10　Stringクラス（substringメソッド）

---Java---
String s = "Java Programming";

substring(開始インデックス, 終了インデックス) は
開始インデックス以上、終了インデックス未満の部分文字列を返します。

  "Java Programming"

・選択肢2: "Jav" は substring(0, 3) の結果です。
・選択肢3: "ava" は substring(1, 4) の結果です。
・選択肢4: "Java P" は substring(0, 6) の結果です。

【ポイント】
  substring(a, b) → インデックス a 以上 b 未満（b は含まない）


問題11　Stringクラス（equalsメソッド）
-------------------------------------------------------------------
以下のコードの実行結果として正しいものを選べ。

---Java---
String a = "Hello";
String b = "hello";
System.out.println(a.equals(b));
System.out.println(a.equalsIgnoreCase(b));
----------

1. true / true
2. false / true
3. false / false
4. true / false

正答: 2

解説:
・equals(str) : 大文字・小文字を区別して比較します。
・equalsIgnoreCase(str) : 大文字・小文字を区別せずに比較します。

  "Hello".equals("hello")           → false（大文字・小文字が異なる）
  "Hello".equalsIgnoreCase("hello") → true（大文字・小文字を無視）

・選択肢1: equals は大文字・小文字を区別するため false です。
・選択肢2: 正解。false / true。
・選択肢3: equalsIgnoreCase は大文字・小文字を無視するため true です。
・選択肢4: equalsIgnoreCase で false になることはありません。

【ポイント】
  文字列の比較は必ず equals() を使う（== は参照比較のため使わない）。


問題12　Stringクラス（==による比較の注意）
-------------------------------------------------------------------
以下のコードの実行結果として正しいものを選べ。

---Java---
String s1 = new String("Java");
String s2 = new String("Java");
System.out.println(s1 == s2);
System.out.println(s1.equals(s2));
----------

1. true / true
2. false / false
3. false / true
4. true / false

正答: 3

解説:
== はオブジェクトの参照（メモリアドレス）を比較します。
new String() でそれぞれ別のオブジェクトを作ると、
中身が同じでも別の参照になるため == は false になります。

  s1 == s2 → false（異なるオブジェクト）
  s1.equals(s2) → true（中身が同じ "Java"）

・選択肢1: == が true になるのはリテラルの文字列プールを使う場合。
・選択肢2: equals は内容を比較するため true になります。
・選択肢3: 正解。false / true。
・選択肢4: equals が false になることはありません。

【ポイント】
  String の比較には必ず equals() を使う！
  == は参照の比較であり、内容の比較ではない。


問題13　ラッパークラス（Integer.parseInt）
-------------------------------------------------------------------
以下のコードの実行結果として正しいものを選べ。

---Java---
String s = "42";
int n = Integer.parseInt(s);
System.out.println(n + 8);
----------

1. 428
2. 50
3. コンパイルエラー
4. 実行時エラー

正答: 2

解説:
Integer.parseInt(文字列) は文字列を int 型の数値に変換します。

  String s = "42";
  int n = Integer.parseInt(s);  // n = 42（数値）
  System.out.println(n + 8);   // 42 + 8 = 50

・選択肢1: 428 は文字列の連結です。n は int型なので数値の足し算になります。
・選択肢2: 正解。42 + 8 = 50。
・選択肢3: Integer.parseInt は正しいメソッドです。
・選択肢4: "42" は数値に変換できる文字列のため実行時エラーは発生しません。

【ポイント】
  数値に変換できない文字列（"abc"など）を parseInt するとNumberFormatException が発生します。


問題14　ラッパークラス（オートボクシング）
-------------------------------------------------------------------
以下のコードの説明として正しいものを選べ。

---Java---
Integer a = 100;
int b = a;
System.out.println(b);
----------

1. コンパイルエラーが発生する。Integer型はint型に代入できない。
2. オートボクシング／アンボクシングにより自動的に変換され、100が表示される。
3. 実行時例外（NullPointerException）が発生する。
4. 0が表示される。

正答: 2

解説:
オートボクシング（Auto Boxing）とは、プリミティブ型とラッパークラス型を
自動的に変換する仕組みです。

  Integer a = 100;   // int → Integer に自動変換（ボクシング）
  int b = a;         // Integer → int に自動変換（アンボクシング）

・選択肢1: Java 5以降はオートボクシングにより自動変換されるためエラーなし。
・選択肢2: 正解。自動変換されて 100 が表示される。
・選択肢3: null ではないため NullPointerException は発生しません。
・選択肢4: 0 ではなく 100 が表示されます。

【ポイント】
  ボクシング  : プリミティブ → ラッパークラス（例: int → Integer）
  アンボクシング: ラッパークラス → プリミティブ（例: Integer → int）


問題15　抽象クラス（abstract）の宣言
-------------------------------------------------------------------
抽象クラスの説明として正しいものを選べ。

1. 抽象クラスはnewキーワードで直接インスタンスを生成できる。
2. 抽象クラスはabstractメソッドを必ず1つ以上含まなければならない。
3. 抽象クラスはabstractキーワードを使って宣言し、直接インスタンス化できない。
4. 抽象クラスを継承したサブクラスは、抽象メソッドをオーバーライドしなくてよい。

正答: 3

解説:
抽象クラスの特徴:
・abstract キーワードで宣言する
・直接インスタンス化できない（new できない）
・抽象メソッド（abstract void メソッド名();）を含めることができる
・抽象メソッドがなくても abstract クラスにはできる

・選択肢1: 抽象クラスは new でインスタンス化できません。
・選択肢2: 抽象メソッドが1つも無い abstract クラスも作れます。
・選択肢3: 正解。abstract キーワードで宣言し、直接インスタンス化できない。
・選択肢4: 抽象クラスを継承した具象クラスは抽象メソッドを必ずオーバーライドしなければなりません（しなければコンパイルエラー）。


問題16　抽象クラス（抽象メソッドのオーバーライド）
-------------------------------------------------------------------
以下のコードでコンパイルエラーが発生するクラスを選べ。

---Java---

----------

解説:
抽象クラスを継承した具象クラス（abstractではないクラス）は、
親クラスのすべての抽象メソッドをオーバーライドしなければなりません。

・選択肢1: draw() を正しく実装しているためエラーなし。
・選択肢2: 正解。draw() を実装していないためコンパイルエラー。
・選択肢3: abstract クラスが abstract クラスを継承する場合、
  抽象メソッドの実装は不要です。エラーなし。
・選択肢4: 空のメソッドでも実装とみなされるためエラーなし。


問題17　finalキーワード（変数）
-------------------------------------------------------------------
以下のコードでコンパイルエラーになる行として正しいものを選べ。

---Java---
final int MAX = 100;  // A
MAX = 200;            // B
System.out.println(MAX);
----------

1. A行（final int MAX = 100;）
2. B行（MAX = 200;）
3. A行とB行の両方
4. エラーは発生しない

正答: 2

解説:
final 変数は一度値が代入されると変更できません（定数）。

  final int MAX = 100;  // ← 初期化（OK）
  MAX = 200;            // ← 再代入（コンパイルエラー！）

・選択肢1: 初期化はOKです。
・選択肢2: 正解。final 変数への再代入はコンパイルエラー。
・選択肢3: A行はエラーになりません。
・選択肢4: B行はエラーになります。

【ポイント】
  final 変数 = 定数（一度代入したら変更不可）
  命名規約: 定数は全て大文字（例: MAX_VALUE, PI）

問題21　superキーワード（スーパークラスのメソッド呼び出し）
-------------------------------------------------------------------
以下のコードの実行結果として正しいものを選べ。

---Java---
class Animal {
    void speak() { System.out.println("..."); }
}
class Dog extends Animal {
    void speak() {
        super.speak();
        System.out.println("ワン");
    }
}

// mainメソッド内
Dog d = new Dog();
d.speak();
----------

1. ワン
2. ...
3. ...
   ワン
4. ワン
   ...

正答: 3

解説:
super.メソッド名() でスーパークラスのメソッドを呼び出せます。

  Dog.speak() の中で:
    1. super.speak() → Animal.speak() が実行 → "..." が表示
