ステップ１：【@RequestMapping アノテーション】に関する問題

問１. 以下のコードの説明として誤っているものを選べ。

---Java---
@Controller
@RequestMapping("/product")
public class ProductController {

    @RequestMapping(value = "/list", method = RequestMethod.GET)
    public String list(Model model) {
        return "product/list";
    }

    @RequestMapping(value = "/list", method = RequestMethod.POST)
    public String search(ProductSearchForm form, Model model) {
        return "product/list";
    }
}
----------

1. クラスに付与した @RequestMapping("/product") と、メソッドに付与した @RequestMapping(value = "/list") は組み合わせて解釈されるため、実際のURLは「/product/list」になる。
2. GETリクエストで「/product/list」にアクセスすると list() が実行される。
3. POSTリクエストで「/product/list」にアクセスすると search() が実行される。
4. クラスとメソッドの両方に @RequestMapping を付与すると、クラス側の指定は無効になりメソッド側の value のみが有効になる。

正解：4番

ステップ７：【セッションスコープを利用するメソッド定義】に関する問題

問７. 以下の2つのコードを比較した説明として正しいものを選べ。

---Java（パターンA）---
@Controller
@SessionScope
public class CartController {
    @Autowired
    private CartForm cartForm;
}
----------

---Java（パターンB）---
@Controller
public class CartController {
    @Autowired
    private CartForm cartForm;

    @PostMapping("/cart/add")
    public String addToCart(CartForm form, HttpSession session) {
        session.setAttribute("cart", form);
        return "redirect:/cart";

----------

3. パターンAの @SessionScope はメソッドにのみ付与可能であるため、このコードはエラーになる。
4. パターンBの session.setAttribute は、セッションではなくリクエストスコープに値を保存する。

ステップ８：【セッションスコープへの値の保存】に関する問題

問８. 以下のコードの説明として誤っているものを選べ。

---Java---
@PostMapping("/login")
public String login(LoginForm form, HttpSession session, Model model) {
    UserEntity user = userService.findByEmail(form.getEmail());
    session.setAttribute("loginUser", user);
    model.addAttribute("message", "ログインしました。");
    return "redirect:/top";
}
----------

1. session.setAttribute("loginUser", user) によりログインユーザーがセッションスコープに保存され、複数のリクエストをまたいで参照できる。
2. model.addAttribute("message", "ログインしました。") で追加した値は、リダイレクト後のビューにも引き継がれる。
3. session.setAttribute で保存した値は、ブラウザを閉じるかセッションタイムアウトになるまで保持される。
4. リダイレクト後のリクエストでは新たなリクエストスコープが生成されるため、model.addAttribute の値はリダイレクト先では参照できない。

正解：2番

ステップ１０：【主キー列でシーケンスを利用するエンティティの定義】に関する問題

問１０. 以下のコードの説明として誤っているものを選べ。

---Java---
@Entity
@Table(name = "invoices")
public class Invoice {

    @Id
    @GeneratedValue(strategy = GenerationType.SEQUENCE, generator = "invoice_gen")
    @SequenceGenerator(
        name = "invoice_gen",
        sequenceName = "invoice_id_seq",
        allocationSize = 1
    )
    private Integer id;

    private String invoiceNumber;
    private Integer totalAmount;

    // getter/setter 省略
}
----------

1. @SequenceGenerator の name 属性（"invoice_gen"）は、@GeneratedValue の generator 属性と一致させる必要がある。
2. @SequenceGenerator の sequenceName 属性（"invoice_id_seq"）には、Java側で定義した任意の名前を指定する。
3. allocationSize = 1 を指定することで、DBのシーケンスが1ずつ採番されることを示している。
4. @GeneratedValue の strategy = GenerationType.SEQUENCE はシーケンスを使った主キー自動生成を意味する。

正解：2番

ステップ１１：【エンティティを利用してDBに登録する処理】に関する問題

問１１. 以下のコードの説明として不具合の原因とならないものを選べ。
（3つの選択肢が不具合の原因、1つだけが正しい処理である）

---Java---
@Service
public class StockService {

    @Autowired
    private StockRepository stockRepository;

    public void register(StockForm form) {

        Stock stock = new Stock();           // (A)
        stock.setId(99);                     // (B) 固定IDをセット
        stock.setProductName(form.getProductName());  // (C)
        stock.setQuantity(form.getQuantity());         // (D)
        stockRepository.save(stock);         // (E)
    }
}
----------

1. (A) Stock エンティティのオブジェクトを new で生成している。
2. (B) IDに固定値「99」をセットすると、既存のIDが99のレコードが上書き（UPDATE）される可能性がある。
3. (B) IDに固定値をセットすると、シーケンスやIDENTITYによる自動採番が無効になる。
4. (E) save() を呼ぶ前に IDが設定されているため、新規登録ではなく更新処理として実行される場合がある。

正解：1番

@Entity
@Table(name = "order_items")
public class OrderItem {

    @ManyToOne

4. OrderItem を save() するとき、order と product フィールドにエンティティオブジェクトをセットすることで外部キーが保存される。

ステップ１４：【@Query によるJPQLの定義】に関する問題

問１４. 以下のコードの説明として正しいものを選べ。

---Java---
public interface OrderRepository extends JpaRepository<Order, Integer> {

    @Query("SELECT o FROM Order o WHERE o.customer.id = :customerId ORDER BY o.createdAt DESC")
    List<Order> findByCustomerId(@Param("customerId") Integer customerId);

ステップ１６：【@NotNull と Integer 型のバリデーション】に関する問題

問１６. 以下のコードの説明として正しいものを選べ。

---Java---
public class PurchaseForm {

    @NotBlank(message = "商品名を入力してください。")
    private String productName;

    @NotNull(message = "数量を入力してください。")
    private Integer quantity;

    @Min(value = 1, message = "数量は1以上を入力してください。")
    private Integer quantity2;

    // getter/setter 省略
}
----------

1. @NotNull は quantity が null（未入力）の場合にエラーになるが、0を入力した場合はエラーにならない。
2. @NotNull は quantity が null の場合だけでなく、0を入力した場合もエラーになる。
3. @NotBlank を Integer 型の quantity に付与すると、数値の形式チェックができる。
4. @Min(value = 1) は @NotNull を含んでいるため、quantity2 が null でもバリデーションエラーにならない。

正解：1番

ステップ２１：【個別画面をレイアウトテンプレートに埋め込む記述】に関する問題

問２１. 以下のコードの説明として誤っているものを選べ。

---Thymeleaf（レイアウトテンプレート layout/base.html）---
<!DOCTYPE html>
<html xmlns:th="http://www.thymeleaf.org"
      xmlns:layout="http://www.ultraq.net.nz/thymeleaf/layout">
<head>
  <title>共通タイトル</title>
</head>
<body>
  <header>共通ヘッダー</header>
  <main layout:fragment="content">
    <p>ここに個別コンテンツが入ります。</p>
  </main>
  <footer>共通フッター</footer>
</body>
</html>
----------

---Thymeleaf（個別画面 product/list.html）---
<!DOCTYPE html>
<html xmlns:th="http://www.thymeleaf.org"
      xmlns:layout="http://www.ultraq.net.nz/thymeleaf/layout"
      layout:decorate="~{layout/base}">
<body>
  <div layout:fragment="content">
    <h2>商品一覧</h2>
    <ul>
      <li th:each="p : ${products}" th:text="${p.name}">商品名</li>
    </ul>
  </div>
</body>
</html>
----------

1. 個別画面の layout:decorate="~{layout/base}" により、layout/base.html をレイアウトテンプレートとして使用することを宣言している。
2. 個別画面の layout:fragment="content" ブロックが、レイアウトテンプレートの同名 layout:fragment="content" に差し込まれる。
3. レイアウトテンプレートに記述した header タグと footer タグは、個別画面をレンダリングしても表示されない。
4. 個別画面に layout:decorate を記述することで、レイアウトテンプレートを使ったレイアウト合成が行われる。

正解：3番
