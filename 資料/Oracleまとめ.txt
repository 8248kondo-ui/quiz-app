# Oracle / SQL 完全解説

データベースとは、大量のデータを整理して保存し、素早く取り出せるようにした「データの倉庫」です。Oracle Databaseは世界で最も多く使われている商用リレーショナルデータベースの一つで、大企業の基幹システム・金融・医療など、信頼性が求められる現場で圧倒的なシェアを誇ります。

この教科書では、初めてDBを学ぶ方でも理解できるよう、身近なたとえを使いながら丁寧に解説します！

---

## 第1部：データベースの基礎概念

### 1. リレーショナルデータベース（RDB）とは？

RDB（Relational DataBase）は、データを**表（テーブル）**の形式で管理するデータベースです。Excelの表に似ていますが、複数の表を「関係（リレーション）」で繋ぐことで、複雑な情報も整理して管理できます。

**たとえ話**: 学校を管理するシステムを考えてみましょう。
- 「生徒テーブル」（生徒番号・名前・クラス番号）
- 「クラステーブル」（クラス番号・クラス名・担任）
この2つを「クラス番号」で繋ぐことで、「田中さんは3年2組で担任は山田先生だ」と分かります。

**重要な用語の整理**:
・**テーブル（表）**: データを格納する表。Excelのシート1枚のようなもの。
・**行（レコード）**: 横1行。1件分のデータを表します。（例: 田中さんという1人の社員のデータ）
・**列（カラム）**: 縦1列。データの「種類」を表します。（例: 「氏名」列・「給与」列）
・**主キー（Primary Key / PK）**: 各行を一意に識別する列。絶対に重複しない・NULLにならない。（例: 社員番号、学生ID）
・**外部キー（Foreign Key / FK）**: 他のテーブルの主キーを参照する列。テーブル間の「橋渡し」役。
・**NULL**: 「値が存在しない・未入力」を表す特別な状態。「0」や「空文字」とは全く別物！

### 2. SQLとは？

SQL（Structured Query Language）は、RDBを操作するための「命令語（言語）」です。大きく4種類に分類されます。

・**DML（Data Manipulation Language）: データ操作言語**
  → `SELECT`（検索）・`INSERT`（追加）・`UPDATE`（更新）・`DELETE`（削除）
・**DDL（Data Definition Language）: データ定義言語**
  → `CREATE TABLE`（テーブル作成）・`ALTER TABLE`（変更）・`DROP TABLE`（削除）
・**DCL（Data Control Language）: データ制御言語**
  → `GRANT`（権限付与）・`REVOKE`（権限剥奪）
・**TCL（Transaction Control Language）: トランザクション制御言語**
  → `COMMIT`（確定）・`ROLLBACK`（取消）

## 第2部：基本のデータ操作（DML）

### 1. SELECT文（データの検索・取得）

最も使う命令です。「どのテーブルから（FROM）・どの条件で（WHERE）・どの列を（SELECT）取り出すか」を指定します。

```sql
-- 基本構文: SELECT 列名 FROM テーブル名 WHERE 条件;

-- ①すべての列を取得（*はすべての列を意味する）
SELECT * FROM 社員;

-- ②特定の列だけを取得
SELECT 社員番号, 氏名, 給与 FROM 社員;

-- ③WHERE句で条件を指定して絞り込む
SELECT 氏名, 給与 FROM 社員 WHERE 給与 >= 300000;

-- ④複数条件の組み合わせ
-- AND: 両方の条件を満たす行だけ
SELECT * FROM 社員 WHERE 部署名 = '営業部' AND 給与 >= 250000;
-- OR: どちらかの条件を満たす行
SELECT * FROM 社員 WHERE 部署名 = '営業部' OR 部署名 = '開発部';

-- ⑤LIKE演算子（あいまい検索）
-- %: 任意の文字列（何文字でもOK）  _: 任意の1文字
SELECT * FROM 社員 WHERE 氏名 LIKE '田%';   -- 「田」から始まる名前
SELECT * FROM 社員 WHERE 氏名 LIKE '%子';   -- 「子」で終わる名前
SELECT * FROM 社員 WHERE 氏名 LIKE '%山%';  -- 名前に「山」を含む

-- ⑥IS NULL / IS NOT NULL（NULLの検索）
-- NULLは = では比較できない！必ずIS NULLを使う
SELECT * FROM 社員 WHERE 上司ID IS NULL;     -- 上司がいない社員（=社長）
SELECT * FROM 社員 WHERE 上司ID IS NOT NULL; -- 上司がいる社員

-- ⑦IN演算子（複数の値のどれかに一致）
SELECT * FROM 社員 WHERE 部署名 IN ('営業部', '開発部', '人事部');

-- ⑧BETWEEN演算子（範囲指定）
-- BETWEEN A AND B: AからBの範囲（AとBを含む）
SELECT * FROM 社員 WHERE 給与 BETWEEN 200000 AND 400000;
```

### 2. ORDER BY（並び替え）と DISTINCT（重複排除）

```sql
-- ORDER BY: 結果を指定した列で並び替える
-- DESC = 降順（大きい順）, ASC = 昇順（小さい順）。デフォルトはASC
SELECT 氏名, 給与 FROM 社員 ORDER BY 給与 DESC; -- 給与が高い順

-- 複数条件のソート（まず部署名の昇順、同じ部署内では給与の降順）
SELECT * FROM 社員 ORDER BY 部署名 ASC, 給与 DESC;

-- DISTINCT: 重複する値を取り除いて表示する
SELECT DISTINCT 部署名 FROM 社員; -- 存在する部署名を重複なしで一覧表示
```

### 3. INSERT, UPDATE, DELETE

```sql
-- データの追加（INSERT）
INSERT INTO 社員 (社員番号, 氏名, 部署名, 給与)
VALUES ('E010', '新人 太郎', '開発部', 200000);

-- データの更新（UPDATE）
-- ！！WHERE句を忘れると、テーブルの全行が更新されてしまう！！絶対注意！
UPDATE 社員
SET 給与 = 給与 * 1.05  -- 給与を5%アップ
WHERE 社員番号 = 'E005'; -- この社員だけを更新する

-- データの削除（DELETE）
-- ！！WHERE句を忘れると、テーブルの全行が削除されてしまう！！絶対注意！
DELETE FROM 社員 WHERE 社員番号 = 'E010';
```

## 第3部：集計関数とGROUP BY

### 1. 集計関数（Aggregate Functions）

複数の行を計算して、1つの値にまとめる関数です。

| 関数 | 説明 | 注意点 |
|---|---|---|
| `COUNT(*)` | 全行数を数える | NULLの行も数える |
| `COUNT(列名)` | その列がNULLでない行数を数える | NULLは数えない |
| `SUM(列名)` | 合計を求める | 数値型の列に使う |
| `AVG(列名)` | 平均を求める | NULLの行は計算対象外 |
| `MAX(列名)` | 最大値を求める | 文字列にも使える |
| `MIN(列名)` | 最小値を求める | 文字列にも使える |

```sql
-- 社員の総数を取得
SELECT COUNT(*) AS 総社員数 FROM 社員;

-- 平均給与と最高給与を同時に取得
-- AS: 列に「別名（エイリアス）」をつける
SELECT AVG(給与) AS 平均給与, MAX(給与) AS 最高給与 FROM 社員;
```

### 2. GROUP BY（グループ化）と HAVING（グループへの絞り込み）

```sql
-- 部署ごとに人数と平均給与を集計する
SELECT 部署名, COUNT(*) AS 人数, AVG(給与) AS 平均給与
FROM 社員
GROUP BY 部署名   -- 「部署名が同じ行」をグループとしてまとめる
ORDER BY 平均給与 DESC;

-- HAVING: GROUP BY の後のグループに対して条件を絞り込む
-- 【重要】WHERE と HAVING の違い:
--   WHERE  = GROUP BY（集計）の「前」に行をフィルタする
--   HAVING = GROUP BY（集計）の「後」にグループをフィルタする
SELECT 部署名, COUNT(*) AS 人数
FROM 社員
WHERE 給与 >= 200000       -- ←まず給与20万以上の行だけに絞る（集計前）
GROUP BY 部署名
HAVING COUNT(*) >= 5;      -- ←さらに人数が5人以上のグループだけに絞る（集計後）
```

### 3. SQLの実行順序（とても重要！）

SQLは書く順番と**実行される順番が違います**。これを理解しているかどうかで、バグを素早く直せるかが変わります。

**実行順序**: `FROM` → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` → `ORDER BY`

つまり、SELECTで付けた「別名（AS）」はWHERE句では使えません（WHEREはSELECTより前に実行されるから）。HAVINGでは使える場合があります（DBによる）。

## 第4部：テーブルの結合（JOIN）

複数のテーブルを繋いで、関連するデータを一度に取り出す技術です。実務では必須です！

**なぜJOINが必要？**: 1つのテーブルにすべての情報を入れると、データが重複して増えてしまいます（例: 社員1000人全員の行に部署の所在地を書くと無駄）。情報を別テーブルに分けて管理し、JOINで繋いで使います。

### 1. INNER JOIN（内部結合）

**両方のテーブルで一致するデータがある行だけ**を取得します。最もよく使います。

```sql
-- 社員テーブルとidで部署テーブルを結合して、部署名も一緒に取得する
-- 「s」と「d」はテーブルの別名（エイリアス）。長いテーブル名を省略するために使う
SELECT s.社員番号, s.氏名, d.部署名, d.所在地
FROM 社員 s
INNER JOIN 部署 d ON s.部署ID = d.部署ID;
-- ON の後に「どの列を使って結合するか」を書く
-- 部署IDが一致する社員と部署の行だけが結果に含まれる
-- ＝部署IDが未設定の社員は表示されない
```

### 2. LEFT OUTER JOIN（左外部結合）

左のテーブル（FROM句）の**全行**を取得します。右のテーブルに一致するデータがない場合はNULLで補います。

```sql
-- 部署未設定の社員も含め、全社員を表示したい場合
SELECT s.氏名, d.部署名
FROM 社員 s                       -- ← 「左」のテーブル（全行が必ず出る）
LEFT OUTER JOIN 部署 d ON s.部署ID = d.部署ID;
-- 部署IDが未設定の社員の行も表示される。その行のd.部署名はNULLになる
```

### 3. RIGHT OUTER JOIN と FULL OUTER JOIN

```sql
-- RIGHT: 右テーブル（部署）の全行を取得。社員がいない部署も表示される
SELECT s.氏名, d.部署名
FROM 社員 s
RIGHT OUTER JOIN 部署 d ON s.部署ID = d.部署ID;

-- FULL: 両方のテーブルの全行を取得。どちらかにしか存在しない行はNULLで補完
SELECT s.氏名, d.部署名
FROM 社員 s
FULL OUTER JOIN 部署 d ON s.部署ID = d.部署ID;
```

### 4. JOIN の使い分けまとめ

| JOIN種類 | 結果 |
|---|---|
| INNER JOIN | 両方に存在するデータだけ取得 |
| LEFT OUTER JOIN | 左テーブルは全件 + 右に一致するもの |
| RIGHT OUTER JOIN | 右テーブルは全件 + 左に一致するもの |
| FULL OUTER JOIN | 両テーブルの全件（どちらかにしかなければNULL） |

## 第5部：サブクエリ（副問合せ）

SQLの中にさらにSQLを書き込む技術です。複雑な問い合わせを表現できます。

```sql
-- ①WHERE句のサブクエリ: 平均給与より高い給与をもらっている社員を検索
SELECT 氏名, 給与
FROM 社員
WHERE 給与 > (SELECT AVG(給与) FROM 社員);
-- 括弧の中のSQLが先に実行されて、平均給与（例: 320000）が求まる
-- その後、外側のSQLで給与 > 320000 の条件で検索される

-- ②FROM句のサブクエリ（インラインビュー）: サブクエリの結果を仮テーブルとして扱う
SELECT 部署名, 平均給与
FROM (
    SELECT 部署名, AVG(給与) AS 平均給与
    FROM 社員
    GROUP BY 部署名
) sub  -- FROM句のサブクエリには必ず別名(エイリアス)が必要
WHERE 平均給与 > 300000;
```

## 第6部：トランザクションとデータの整合性

### 1. トランザクションとは？

複数のSQL文を「不可分な1つの処理のまとまり」として扱う仕組みです。

**なぜ必要？** 銀行の振込を例に考えます。
- A口座から10,000円を引き落とす（UPDATE）
- B口座に10,000円を入金する（UPDATE）

この2つのUPDATEのうち、1つ目だけ成功して2つ目でエラーが起きたら、お金が消えてしまいます！
トランザクションを使えば「2つセットで成功するか、2つセットで失敗するか」を保証できます。

**OracleのトランザクションはDMLを実行した瞬間に自動で始まります**（他のDBとは異なる点！）。
`COMMIT` で確定、`ROLLBACK` で取り消しを行います。

```sql
-- Oracleのトランザクションの例
-- ※OracleではBEGIN TRANSACTIONは不要。DMLを書いた瞬間にトランザクション開始

UPDATE 口座 SET 残高 = 残高 - 10000 WHERE 口座番号 = 'A001'; -- 引き落とし
UPDATE 口座 SET 残高 = 残高 + 10000 WHERE 口座番号 = 'B002'; -- 入金

-- 問題なければ COMMIT で変更を「確定」する（他のユーザーに見えるようになる）
COMMIT;

-- エラーが起きた場合は ROLLBACK で「取り消し」する（COMMIT前の状態に戻る）
-- ROLLBACK;
```

**ACID特性（トランザクションが守るべき4つの性質）**:
・**Atomicity（原子性）**: 処理は「全部成功」か「全部失敗」のどちらか。中途半端はない。
・**Consistency（一貫性）**: 処理の前後でデータの整合性が保たれる。（口座残高がマイナスにならないなど）
・**Isolation（分離性）**: 複数のトランザクションが同時に動いても互いに干渉しない。
・**Durability（永続性）**: 一度COMMITしたデータは、障害が起きても消えない。

### 2. インデックス（INDEX）とパフォーマンス

インデックスとは、本の「索引（目次）」のようなものです。インデックスがない場合、特定のデータを探すには全ページをめくって確認する必要があります（全行スキャン = フルスキャン）。インデックスがあれば、「索引」から直接ページを参照できます。

```sql
-- 「氏名」列によく検索をかける場合、インデックスを作成する
CREATE INDEX idx_社員_氏名 ON 社員 (氏名);

-- インデックスの確認（Oracleのシステムテーブルから確認）
SELECT index_name, table_name FROM user_indexes WHERE table_name = '社員';

-- インデックスの削除
DROP INDEX idx_社員_氏名;
```

**インデックスの注意点**:
・✅ メリット: SELECTのWHERE検索が劇的に速くなる
・❌ デメリット: INSERT/UPDATE/DELETE時にインデックスも更新するため若干遅くなる。また余分な記憶容量が必要。
→ 「よく検索に使う列」に絞って作成するのが適切です。

## 第7部：DDL（テーブル定義）と制約

### 1. テーブルの作成（CREATE TABLE）

```sql
CREATE TABLE 社員 (
    社員番号  VARCHAR2(10)  NOT NULL,           -- NOT NULL: 空欄（NULL）禁止
    氏名      VARCHAR2(50)  NOT NULL,
    生年月日  DATE,                             -- NULLを許可（省略時）
    給与      NUMBER(8, 0),                     -- 最大8桁の整数
    部署ID    NUMBER(5)
              REFERENCES 部署(部署ID),          -- 外部キー制約: 部署テーブルを参照
    
    CONSTRAINT PK_社員 PRIMARY KEY (社員番号)   -- 主キー制約（重複・NULL禁止）
);
```

### 2. 主要なOracleデータ型

| データ型 | 説明 | 使用例 |
|---|---|---|
| `NUMBER(p, s)` | 数値。pは全体の桁数、sは小数以下の桁数 | NUMBER(8,2)→最大8桁で小数2位 |
| `VARCHAR2(n)` | 可変長の文字列。入れた分だけ容量を使う | VARCHAR2(100)→最大100文字 |
| `CHAR(n)` | 固定長の文字列。常にn文字分の容量を使う | CHAR(10)→常に10文字分 |
| `DATE` | 日付と時刻（年月日時分秒まで） | 入社日、生年月日など |
| `TIMESTAMP` | 高精度の日付時刻（ナノ秒まで） | ログの記録時刻など |
| `CLOB` | 大きなテキストデータ | 長文の説明、メモなど |

### 3. テーブルの変更と削除

```sql
-- 列を追加する
ALTER TABLE 社員 ADD メールアドレス VARCHAR2(100);

-- 列の定義を変更する（サイズ変更など）
ALTER TABLE 社員 MODIFY 給与 NUMBER(10, 0);

-- 列を削除する
ALTER TABLE 社員 DROP COLUMN メールアドレス;

-- テーブルを完全に削除（中のデータもすべて消える！取り消し不可！）
DROP TABLE 社員;
```

## 第8部：便利な関数

### 1. 文字列関数

```sql
-- 大文字・小文字変換
SELECT UPPER('hello') FROM dual;  -- 'HELLO'
SELECT LOWER('HELLO') FROM dual;  -- 'hello'

-- 文字列の一部を切り出す（開始位置, 文字数）
-- ※Oracleのインデックスは1から始まる！
SELECT SUBSTR('ABCDE', 2, 3) FROM dual;  -- 'BCD'（2文字目から3文字分）

-- 文字数を返す
SELECT LENGTH('こんにちは') FROM dual;  -- 5

-- 文字列を置換する（対象文字列, 検索文字, 置換後の文字）
SELECT REPLACE('AABBCC', 'BB', 'XX') FROM dual;  -- 'AAXXCC'

-- 前後の空白（または指定文字）を除去する
SELECT TRIM('  hello  ') FROM dual;  -- 'hello'
```

### 2. 数値関数

```sql
-- 四捨五入（数値, 小数点以下の桁数）
SELECT ROUND(123.456, 1) FROM dual;   -- 123.5

-- 切り捨て（数値, 小数点以下の桁数）
SELECT TRUNC(123.456, 1) FROM dual;   -- 123.4（切り捨て。ROUNDとの違いに注意）

-- 余りを求める
SELECT MOD(10, 3) FROM dual;   -- 1（10÷3の余り）

-- 絶対値を求める
SELECT ABS(-50) FROM dual;   -- 50
```

### 3. 日付関数

```sql
-- 現在の日付と時刻を返す
SELECT SYSDATE FROM dual;  -- 例: 2026/05/21 17:30:00

-- 2つの日付の月数の差を返す
SELECT MONTHS_BETWEEN(SYSDATE, 入社日) FROM 社員;

-- 指定した月数を加算した日付を返す
SELECT ADD_MONTHS(SYSDATE, 3) FROM dual;  -- 3ヶ月後の日付

-- 日付を文字列に変換する（書式を指定できる）
SELECT TO_CHAR(SYSDATE, 'YYYY/MM/DD') FROM dual;  -- '2026/05/21'

-- 文字列を日付型に変換する（書式を文字列と一致させる）
SELECT TO_DATE('2026/01/01', 'YYYY/MM/DD') FROM dual;
```

### 4. NULL処理関数（実務で超重要！）

NULLが含まれるデータを扱う際に使います。NULLとの計算は常にNULLになるため注意が必要です。

```sql
-- NVL(列名, NULLの時に使う代替値): NULLなら代替値を返す
SELECT 氏名, NVL(給与, 0) FROM 社員;  -- 給与がNULLなら0として扱う

-- NVL2(列名, NULLでない時の値, NULLの時の値)
SELECT NVL2(部署ID, '配属済み', '未配属') FROM 社員;

-- COALESCE: リストの中で最初のNULLでない値を返す（複数列に対応）
SELECT COALESCE(携帯番号, 固定電話, '連絡先なし') FROM 社員;

-- CASE式: 条件によって返す値を切り替える（Javaのif文のようなもの）
SELECT 氏名,
    CASE
        WHEN 給与 >= 500000 THEN 'A評価（ハイクラス）'
        WHEN 給与 >= 300000 THEN 'B評価（標準）'
        ELSE                     'C評価（要改善）'
    END AS 給与評価
FROM 社員;
```
